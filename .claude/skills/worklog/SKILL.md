# worklog

작업 완료 후 `WORKLOG.md`에 이유(Why), 과정(How), 결과(Result)를 기록하는 스킬.
이 파일은 `.gitignore`에 등록되어 있어 팀에 공유되지 않고 본인만 사용한다.

## 호출 시점

- 사용자가 "작업 기록해줘", "worklog 남겨줘", "로그 남겨줘" 같이 명시적으로 요청할 때
- 큰 단위 작업(Entity 구현, API 완성, 버그 수정 등)이 마무리됐을 때

## WORKLOG.md 위치

프로젝트 루트: `WORKLOG.md`

파일이 없으면 새로 만들고, 있으면 맨 위에 추가(최신 항목이 위에 오도록).

## 항목 형식

```markdown
## [YYYY-MM-DD] <작업 제목>

**이유 (Why)**
왜 이 작업을 했는가. 어떤 문제나 필요가 있었는가.

**과정 (How)**
어떤 순서로 진행했는가. 주요 결정 사항이나 선택지 중 어떤 걸 골랐는가.

**결과 (Result)**
무엇이 만들어졌는가. 이후 어떤 작업과 연결되는가.

---
```

## 작성 원칙

- **이유**: "왜 지금 이 작업인가"를 한두 문장으로. 과제 요구사항, 팀 합의, 기술적 필요 등.
- **과정**: 단계별 나열보다 **핵심 결정과 이유** 위주로. 예: "Groovy DSL 대신 Kotlin DSL 쓴 이유는..." 보다는 결정 자체와 맥락.
- **결과**: 생성/수정된 파일 목록 + 다음 단계와의 연결.
- 분량: 항목당 총 10~20줄 이내. 장황하게 쓰지 않는다.

## 작성 과정

### STEP 1. 현재 대화에서 완료된 작업 파악

대화 컨텍스트에서:
- 어떤 작업을 했는가
- 왜 했는가 (사용자가 설명한 이유 또는 CLAUDE.md의 맥락)
- 어떤 파일이 만들어지거나 수정됐는가

### STEP 2. WORKLOG.md 상태 확인

```
WORKLOG.md가 존재하는지 Read로 확인.
```

없으면 새 파일로 시작. 있으면 기존 내용 앞에 새 항목 추가.

### STEP 3. 항목 작성 후 파일에 기록

형식에 맞춰 항목을 작성하고 Write 또는 Edit으로 저장.

새 항목이 항상 파일 상단에 위치하도록 prepend.

### STEP 4. 완료 보고

"WORKLOG.md에 기록했습니다." 한 줄로 종료. 내용을 다시 출력하지 않는다.

## 예시 항목

```markdown
## [2026-05-08] 백엔드 초기 셋업 (Gradle + Entity + 레시피 도메인)

**이유 (Why)**
Week 1 개발을 시작하기 위해 빌드 환경과 도메인 모델이 먼저 필요했다. 손유경의 DDL 작업과 병렬로 진행하기 위해 Entity 구조를 먼저 잡아두었다.

**과정 (How)**
Spring Initializr로 Gradle + Spring Boot 3.5.0 + JPA + MariaDB + Lombok 구성으로 프로젝트를 생성했다. Entity 7개는 CLAUDE.md의 테이블 명세를 기준으로 작성했으며, DDL이 확정되면 필드명을 맞추는 방식으로 진행하기로 했다. 트리거 연동이 필요한 CookService에는 em.clear()를 미리 넣어두었다.

**결과 (Result)**
build.gradle, Gradle Wrapper, Entity 7개, RecipeRepository(추천 쿼리), CookService(트리거 후 캐시 초기화), ApiResponse<T>, CORS 설정이 완성됐다. 다음 단계: 손유경 DDL 수령 후 Entity 필드명 검증 → bootRun 빌드 확인.

---
```
